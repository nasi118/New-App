# Repository Assessment and Gap Analysis

Date: 2026-07-28 · Assessed at commit `d2b87ee` (initial commit)

## What existed before this work

The repository contained a single 8-byte `README.md` and nothing else — no
languages or frameworks, no data models, no calculation code, no rules or
parameter storage, no database or migrations, no API patterns, no background
jobs, no authentication/authorization, no import/export code, no
spreadsheet-generation code, no tests or fixtures, and no observability or
audit logging.

**Conclusion: greenfield.** There were no working components to preserve or
wrap, so every module below is new. Nothing was replaced.

## Known gaps (deliberate, tracked)

1. **Document import pipeline** — the staged import workflow (upload → map →
   preview → approve → provenance) is specified in docs and represented in the
   audit workbook, but no parser is implemented yet. All inputs currently come
   from user entry with provenance.
2. **Engine tax scope** — see `docs/UNSUPPORTED.md` for the explicit list
   (self-employment/QBI, AMT, state returns, carryforwards, etc.). Unsupported
   situations produce blocking diagnostics that force human review — they are
   never silently approximated.
3. **Persistence** — the store is JSON-file-backed behind a narrow interface;
   swapping in a real database is a storage-layer change only.
4. **CSV schedule exports** — canonical JSON and the Excel package exist; per-
   schedule CSVs are a small follow-up on top of the same line-item data.
